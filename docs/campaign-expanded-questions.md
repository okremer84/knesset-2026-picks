# Expanded Eisenmarkt questions

Implemented October 17, 2026. The operator can generate the new sets under **ניהול → מעקב ואישור → הכנת שאלות מהמקורות**. Select a future observation window; drafts enter the existing queue for editing and publication. Existing funded contracts are unchanged. This checkout has not been deployed or used to publish live markets.

- **Next prime minister:** Netanyahu, Eisenkot, Bennett, Lieberman and other. Portraits use existing local assets. Opening editorial game estimates are 40/35/15/5/5, as a deliberate starting allocation, not researched election probabilities. Each row is an existing independent binary market; quotes need not remain normalized. The first post-election government receiving Knesset confidence controls the outcome; an interim or alternate PM does not count. Choose a window long enough for government formation. No formation in the window means void.
- **Polls:** two questions per available broadcaster (Kan 11, N12, 13, 14), for Likud and a fixed opposition party list. Thresholds come from each publisher's latest locally stored poll, with the stored institute kept separate. The opposition list is `yashar`, `beyachad`, `democrats`, `israel_beitenu`, `kachol_lavan`; Arab and independent parties are excluded. Missing party numbers prevent automatic prefill. Source research found newer publications than some local records; sync and verify primary evidence before publishing. No calibrated poll probability is claimed; drafts start at 50/50.
- **Next interview:** 14/11/12/13/i24/radio/other, with editorial 30/15/10/10/10/15/10 opening estimates. These adapt [the research](netanyahu-interview-research.md) to the existing 5% minimum and a conditional-on-an-interview contract: no interview means void, not a separate priced outcome. No future booking was verified. The original full broadcast determines the venue; ambiguous simultaneous broadcasts void.
- **X:** setup now includes Netanyahu, Lapid, Bennett, Lieberman, Golan and Gantz. The first successful API collection requests up to 90 days of history, stopping once 30 original posts and the complete two-day overlap have been collected, followed by the existing two-day overlap. Ten-page safety cap fails explicitly rather than claiming complete coverage. Existing scheduled collection remains every five minutes. There is no unverified Eisenkot handle.
- **Keywords:** Iran, Qatar/Qatargate, war, conscription/evasion, hostages and elections. Matching is deterministic and shared between sampling and settlement; tokens may count in unrelated contexts. URLs and attachment content are excluded, as are replies and plain reposts. Quote-post author text counts. Existing Iran/Qatar semantics are preserved.

For each account the latest 30 captured original-version posts are analyzed. With 20–30 usable posts, opening probability is `(matching posts + 1) / (sample size + 2)`, bounded to the game's 5–95% range. With fewer than 20, the draft uses `no_basis` at 50%. The operator can see counts and raw percentages separately. Topics overlap, so their percentages need not sum to 100. The history is the collected sample, not a promise that deleted posts were recovered. [Research limitations and verified handles](leader-post-market-research.md).

Live X access and source collection are still required; web search did not yield a complete latest-30 sample. Missing API access remains explicit and blocks publishing monitored X questions. Candidate/interview editorial quotes are excluded from automatic AI repricing so a generic no-basis response cannot overwrite their intentional starting allocation. Manual quote changes remain available.

Validation: backend tests cover idempotent draft creation, published portrait metadata, publisher-specific thresholds, fixed-bloc prefill, keyword boundaries and latest-30 smoothed frequency. Existing campaign tests, frontend suite, TypeScript and production build pass. The browser preview uses explicitly synthetic data.
